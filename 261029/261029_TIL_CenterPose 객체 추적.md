#### YOLO를 쓰는 이유: 물체 후보 찾기
카메라 영상에서 퍽의 종류와 2D 위치를 동시에 찾습니다. 태그가 가려진 장면에서도 학습한 외형으로 후보를 찾을 수 있습니다.

영상 RGB → YOLOv8 클래스·상자·점수 → 대상 후보 선택

YOLO 출력은 클래스·상자·점수입니다. 그 결과만으로 물체의 3D 위치·회전·영구 ID를 알 수는 없습니다.
CenterPose·AprilTag·추적 계층과 역할을 나누어 연결합니다.

#### YOLO가 없을 때와 있을 때
AprilTag만 사용하면 표식이 보이는 물체를 정확한 ID로 구분합니다. YOLO를 더하면 표식이 가려져도
외형에 따른 후보를 얻습니다.

태그 가림 → 외형으로 후보 탐색 → ID 재확인

태그 미검출 → YOLO로 후보 탐색 → 자세·연결 검증 태그를 다시 읽기 전에는 같은 색의 퍽을 같은 ID로
단정하지 않습니다. YOLO가 CenterPose의 필수 전처리인 것은 아닙니다.

#### PyTorch를 쓰는 이유: 오차로 모델 학습
사진과 라벨을 tensor로 만들고 모델의 예측 오차를 계산합니다. 자동미분으로 가중치를 어느 방향으로
바꿀지 구합니다.

입력·정답 tensor → 예측 → loss → 미분 → 가중치 갱신

직접 구현할 부분: Dataset, 손실 함수, 평가 함수 Ultralytics 학습 API는 이 과정의 많은 부분을 대신
제공합니다. YOLO와 PyTorch는 대체 관계가 아니라 모델과 학습 도구의 관계입니다.

#### PyTorch에서 ROS까지: 파일이 바뀌는 이유
PyTorch에서 학습한 가중치를 ONNX 계산 그래프로 내보냅니다. TensorRT는 대상 GPU에서 실행할 엔진을
만듭니다.

PyTorch.pt 가중치 → ONNX → TensorRT 추론 엔진 → ROS 디코더 검출 메시지

ROS 노드는 카메라 입력과 추론 출력을 메시지로 연결합니다. 디코더는 모델 tensor를 클래스·상자·점수로
해석합니다. 학습 프레임워크, 추론 엔진, 통신 프레임워크를 구분합니다.

#### PnP가 푸는 문제

#### 작은 태그의 인식 거리 계산
예시: f_x = 600px, 한 변 = 0.016m
영상 크기 ≈ f_x × 한 변 / 거리
0.5m → 약 19.2px
1.0m → 약 9.6px

실제 태그 크기 s → 거리 Z · 초점 f → 픽셀 크기 p = fs/Z

이 값은 성공 거리 보장이 아닙니다. 기울기·흐림·노출·해상도에 따라 코너와 비트가 사라집니다.
거리별 ID 성공률·자세 오차를 실측하여 접근 거리를 정합니다.

영상 → 검출 → 가림

회전한 시점·가림·화면 경계 샘플을 반드시 포함합니다.

#### BOP: 파일별 역할과 단위
scene_camera.json: 프레임별 cam_K scene_gt.json: cam_R_m2c, cam_t_m2c,
obj_id models/*.ply: 객체 형상과 기준 좌표계

scene_camera / K  →  scene_gt / R·t  →  models / 형상

BOP의 이동·모델 길이 단위를 확인한 뒤 ROS의 m로 변환합니다. t_m = t_mm / 1000; 회전행렬
R은 배율 변환하지 않습니다. 메시 원점·대칭 정보·가려진 상자 정의도 함께 검수합니다.

#### BOP을 CenterPose로 옮길 때의 설계
모델 범주 선택 → 기준 3D 상자 → 꼭짓점 8개와 중심 포즈와 K로 projected_cuboid 9개를 계산합니다.

모델·R·t·K → 상자 중심·점 순서 → TAO 스키마 검수

BOP JSON을 이름만 바꾸어 넣으면 안 됩니다. TAO 로더의 점 순서, scale 정의,
camera_projection_matrix를 맞춥니다. 모델 원점과 상자 중심이 다르면 그 변환도 포함합니다.

#### COCO → YOLO: 좌표 변환식
COCO: [x, y, w, h] — 왼쪽 위와 폭·높이, 픽셀 YOLO: class_id cx cy bw bh — 0~1 정규화
![[Pasted image 20261029110312.png]]
cx = (x + w/2)/W; cy = (y + h/2)/H bw = w/W; bh = h/H 예: W=640, H=480, [100,120,80,60] →
cx=0.21875, cy=0.3125, bw=0.125, bh=0.125

#### 실습: COCO 라벨 변환 실행
동봉 converter는 category_id를 names 순서로 다시 매핑합니다. 경계를 벗어난 상자는
잘라내고 crowd가 포함된 영상은 제외합니다.

클래스 이름 선택  →  ID·상자 변환  →  이미지 겹침 검수

python scripts/coco_to_yolo.py --annotations instances.json \
--images images --out data/coco_subset --categories cup bottle
결과: images/, labels/, dataset.yaml, conversion-report.json
원본 split별로 따로 변환하고 빈 라벨도 검수합니다.

#### 잘못된 클래스 매핑을 그림으로 확인
COCO category_id는 연속 번호라고 가정하지 않습니다. 요청한 클래스 순서가 출력 YOLO의 0, 1, …을
정합니다.

원본 category_id  →  이름으로 선택  →  0부터 새 ID

예: cup → 0, bottle → 1로 설정했다면 YAML도 같은 순서입니다. 이미지 위에 클래스명까지 표시해 서로
뒤바뀌지 않았는지 확인합니다. 빨강 퍽에 cup 정답을 임의로 복사하지 않습니다.

#### 데이터 누수: 프레임을 섞으면 안 되는 이유
연속 영상의 100번과 101번 프레임은 거의 같습니다. 한쪽은 학습, 다른 쪽은 시험에 넣으면 결과가
과대평가됩니다.

세션 A → train  →  세션 B → val  →  새 세션 C → test

촬영 세션·동일 물체·동일 배경을 묶어 split을 고정합니다. 공개 데이터 공식 test는 최종 평가에만
사용합니다. 자체 촬영의 새로운 장소·조명·물체를 별도 holdout으로 남깁니다.

#### 학습 순서: 공개 가중치 → 자체 퍽
공개 사전학습 가중치로 특징 추출을 시작합니다. 자체 퍽의 색·모양 라벨로 출력 클래스를 학습합니다.

공개 가중치   →  자체 퍽 라벨  →  현장 holdout 평가

YOLO("yolov8n.pt").train(data="configs/pucks.yaml", epochs=50) 처음에는 작은 subset에서 한
배치의 손실·예측을 확인합니다. 공개 데이터만으로 우리 카메라의 성능을 판단하지 않습니다.

#### 공개 데이터와 자체 데이터를 섞는 기준
배경·조명 다양성은 도움이 되지만 클래스 정의가 맞아야 합니다. 컵과 퍽을 같은 클래스에 넣는
것은 별도 설계 판단입니다.

A / 자체 데이터  →  같은 평가 영상  →  B / 혼합 데이터

A: 공개 가중치 + 자체 데이터 B: 같은 가중치 + 공개 데이터 일부 + 자체 데이터 같은 holdout에서
검출·자세·지연을 비교하고 혼합 비율을 기록합니다.

#### 오픈데이터 실습의 제출물
① 출처·라이선스·해시 manifest ② 클래스 대응표와 split 목록 ③ 변환 전후 라벨 겹침 이미지

데이터 이력  →  라벨·분할 검수  →  학습·실패 결과

④ 학습 설정·실행 로그·가중치 ⑤ 같은 holdout에서 A/B 비교표 ⑥ 틀린 예시 영상과 수정한 라벨
정책 데이터를 많이 받은 것보다 변환·검증을 설명할 수 있는지가 기준입니다.

#### 두 가지 라벨을 별도로 만들기
YOLO 라벨 클래스 + 정규화한 2D 상자
CenterPose 라벨 카메라 정보 + 3D 기준 상자 투영점·크기·자세 관련 정보

원본 RGB  →  YOLO / 2D 라벨  →  CenterPose / 3D 라벨

AprilTag ID는 메타데이터입니다. 그 자체가 물체의 8개 꼭짓점 정답을 대신하지 않습니다.
기하 정보로 라벨을 생성한 뒤 영상 위 재투영으로 검수합니다.

#### YOLO 라벨링 정책
클래스 예: red_cylinder, green_cylinder red_prism, green_prism
모양과 색을 분리하는 설계도 가능하나 전체 데이터에서 기준을 통일합니다.

클래스 기준 합의  →  가림·절단 기준  →  동일 기준으로 검수

한 객체당 한 상자 가림은 원래 윤곽 추정/가시 영역 중 선택한 기준을 문서화합니다.
경계 밖 객체·심한 흐림·식별 불가 처리 규칙도 합의합니다.

0.25 0.5

#### CenterPose 라벨의 기준점
객체 중심 1점 + 상자 꼭짓점 8점 projected_cuboid는 픽셀 좌표입니다.
상자 꼭짓점 순서는 로더·PnP의 3D 기준점 순서와 맞춥니다.

원본 영상  →  사각형·클래스  →  검수·내보내기

같은 이름의 image.jpg / image.json
현재 TAO 로더의 필드와 학습에 쓰는 버전의 예제 JSON을 직접 대조합니다. YOLO TXT를 이름만 바꾸면 안
됩니다.

#### CenterPose JSON 필드 검사
camera_data.intrinsics fx, fy, cx, cy camera_projection_matrix
objects[].projected_cuboid objects[].scale

camera_data  →  objects / 9개 점  →  크기·순서 검사

대칭 변환·평가에 필요한 필드 quaternion_xyzw, location keypoints_3d
점 좌표계·단위·점 순서가 맞아야 라벨이 의미를 갖습니다.

#### AprilTag로 자세 라벨 보조 생성
태그 자세 + 장착 변환으로 객체 좌표계의 자세를 계산합니다.
실측 3D 상자를 카메라로 변환하고 K로 투영하여 키포인트를 만듭니다.

태그 자세  →  장착 변환  →  객체 라벨 검수

태그가 가려지거나 잘못 해독된 프레임은 자동 승인하지 않습니다.
태그 포즈를 정답으로 썼다면 같은 태그 포즈와의 비교는 독립적인 정확도 검증이 아닙니다.

#### 합성 데이터와 실측 데이터
합성 장면은 물체 자세·카메라 K· 가림 정보를 정확히 기록하기 쉽습니다.
배경·광원·재질·카메라 위치를 변경하며 다양성을 만듭니다.

합성 장면  →  실제 촬영  →  같은 현장 영상 평가

카메라 축·메시 원점·미터 단위와 실제 렌더 영상의 투영점을 대조합니다.
합성 데이터로 학습한 뒤 실제 미로 영상의 실패 분포를 따로 평가합니다.
