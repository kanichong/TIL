14강 · 명령 계약과 ROS 2 Action
명령에 단위·시각을 붙여 검사하고, 오래 걸리는 팔 동작은 Action으로 보내기

ROS 2 · 프로그램이 대화하는 세 방식
노드(node)는 통신의 주체이고, 토픽(topic)은 발행자가 보낸 값을 구독자들이 연속으로 받는 방식입니다.
서비스(service)는 한 요청에 한 응답 → 짧은 질문에 적합, 요청 형식이 같아야 양쪽이 값을 해석함
액션(action)은 오래 걸리는 작업용 → 클라이언트가 목표를 보내고, 서버가 실행하며 중간 피드백 · 최종 결과를 돌려주고, 취소 요청도 받을 수 있음
연속 관측은 Topic, 짧은 조회는 Service, 취소 가능한 장시간 동작은 Action
질문: 3초 동안 팔을 움직이며 중간 각도를 확인하려면? → Action (전체 관절각을 계속 보고 싶으면 joint_states 토픽)

ROS 2 · 월드 좌표와 관절각
좌표계(frame)는 위치를 재는 원점과 축의 방향을 정함 → world는 장면에 고정된 기준이라 로봇이 돌아도 같은 물체의 world 좌표는 그대로일 수 있음
자유도(DOF)는 독립적으로 움직이는 축 · 팔 관절 4개는 각각 회전 · 라디안(rad)은 회전각 단위 (π rad = 180°)
궤적(trajectory)은 시간에 따른 목표들의 순서 → FollowJointTrajectory는 이름이 지정된 관절들이 주어진 시점까지 갈 목표를 전달하는 액션
14강 contract는 월드 좌표 요청을 검사, 별도 action_client 실습은 시작 관절각에서 목표각을 직접 정해 모의 제어기에 보냄

명령 계약 · 수치에 의미를 붙이기
항목  -  뜻
스키마 · version  -  필드 · 순서 · 형식에 관한 약속, version이 command.v1이면 해당 형식을 사용
request_id  -  요청 하나를 식별
unit  -  수치의 단위 (1 m = 1,000 mm)
유한값  -  NaN(정의되지 않은 수)과 무한대는 좌표로 쓸 수 없어 검사에서 거부
age_s  -  관측부터 사용 시점까지 경과한 초 → 오래된 위치에는 물체가 이미 없을 수 있어 0~0.4초만 허용
질문: 좌표와 단위는 두고 age_s를 0.400에서 0.401로 바꾸면? → contract.stale 발생 (경계 실험)

Action · 수락, 피드백, 취소, 종료의 시간차
Goal은 서버가 실행할 목표, 수락하면 그 목표를 가리키는 handle을 받음 → 여러 목표가 오가도 핸들로 원하는 요청의 결과를 조회
비동기(async) 호출은 응답 도착 전에 제어를 돌려줌 · Future는 나중에 채워질 결과 · 콜백(callback)은 피드백이 도착할 때 실행되는 함수
status는 목표의 생애주기, error_code는 제어기의 결과 코드, cancel은 취소 요청
취소 수락 · CANCELED 도달 · 실제 속도 0의 시점은 각각 따로 측정
wait()의 timeout은 “기다릴 시간을 넘겼다”는 뜻일 뿐 → 결과가 미확정이면 같은 목표를 곧바로 중복 전송할 근거가 없음

Action · 모의 제어기로 확인할 수 있는 것
제어기(controller)는 목표를 받아 구동기에 줄 명령을 만듦 → 관절 궤적 제어기는 시간에 맞춰 어느 관절이 어느 각도로 갈지 계산
모의(mock) 하드웨어는 센서 · 구동기 인터페이스를 소프트웨어로 대신 → 실제 모터 연결 전에 서버의 수락 · 취소 · 피드백 처리 절차를 확인
추종 오차 = 목표값 − 관측값 → 관절 이름 순서가 어긋나면 다른 관절끼리 빼게 되므로 joint1~4의 이름과 배열 순서를 먼저 맞춤
Action의 Feedback(서버가 알리는 진행 메시지)과 제어 루프의 피드백(관측을 다음 제어에 쓰는 원리)은 맥락이 다름

Action · 수락한 뒤에 볼 것
단계  -  읽을 내용
Goal  -  팔 관절 이름 · 목표각 · 도달 시간 전달 (좌표 기반 명령이면 프레임 · 단위 · 시각도 검사)
Feedback  -  제어기가 보고한 현재 관절각 읽기, 마지막 시각과 오차를 남김
Result  -  종료 상태와 오류 코드를 함께 읽음, 수락 직후 다음 작업으로 넘어가면 안 됨

15강 · 멀티모달 임베딩과 Grounding
색 이름으로 고른 픽셀을 깊이로 월드 좌표까지 복원하기

용어 · 모달리티, 임베딩, 그라운딩
모달리티  -  정보의 형태. 사진과 문장은 같은 물체를 다른 방식으로 표현. 멀티모달 모델은 여러 형태를 함께 처리
임베딩  -  대상을 숫자 벡터로 나타낸 것. 공통 공간에서는 서로 다른 입력의 벡터를 같은 기준으로 비교 (일반적인 VLM이 이 표현을 학습)
그라운딩  -  “파란 블록”이라는 말이 현재 장면의 어느 대상 · 위치를 가리키는지 정하는 과정. 같은 색 블록이 둘이면 색만으로는 대상을 정하기 어려움
수업의 색상 기준선에서는 파랑을 [0, 0, 1]로 직접 지정 → 이 기준선과 학습된 시각 · 언어 표현의 차이를 설명하는 강의

픽셀에서 파란색 마스크 만들기
픽셀(px)  -  영상 격자의 한 칸. RGB 영상은 칸마다 빨강 · 초록 · 파랑 채널 값을 가짐. 같은 색도 밝기에 따라 세 수의 크기가 달라짐
코사인 유사도  -  두 벡터의 내적 ÷ 각 벡터 길이의 곱. 방향이 같으면 1 (파랑 축과 [0, 0, 100]은 1, [100, 0, 0]은 0)
마스크 · 문턱값  -  마스크는 픽셀마다 포함 여부를 표시, threshold는 포함을 가르는 기준값. 코드에서는 코사인 값과 채널 밝기 조건을 모두 통과해야 함
왜 밝기도 볼까? [0, 0, 1]도 방향은 파랑이지만 매우 어두움 → 파랑 채널이 45를 넘어야 픽셀이 남음

깊이와 카메라 보정값이 필요한 이유
광축 깊이  -  RGB-D의 D는 깊이. Z는 카메라 정면 축을 따라 잰 거리(m). 영상 가장자리에서는 광축 깊이와 카메라~점 직선거리가 다름
내부 파라미터  -  fx, fy는 픽셀 단위 초점거리, cx, cy는 광축이 영상면을 지나는 위치(주점). 주점에서 멀어진 픽셀 수가 시선 방향을 결정
역투영  -  픽셀 (u, v)와 깊이 Z로 광학 좌표의 3차원 점을 구함. 같은 픽셀 방향의 실제 옆 거리는 Z에 비례
```text
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
```
수치 확인: 주점에서 오른쪽 60 px, fx = 600 px, Z = 0.5 m → X = 0.05 m. 한 픽셀만으로는 Z를 정할 수 없음

카메라의 점을 로봇이 쓰는 점으로
외부 보정  -  외부 파라미터는 두 좌표계 사이의 회전 R과 이동 t. optical_to_world는 광학 좌표의 점을 월드 좌표로 표현하는 변환
행렬과 점  -  [X, Y, Z, 1]처럼 끝에 1을 붙이면 회전과 평행이동을 한 번의 행렬 곱으로 적용
중앙값과 표면  -  ground()는 축마다 중앙값을 구해 튀는 깊이의 영향을 줄임. 결과는 카메라가 본 표면을 대표
평행이동 예: 카메라 축이 월드와 평행하고 원점만 X 방향 0.20 m 떨어져 있으면 카메라 X = 0.05 m인 점은 월드 X = 0.25 m

스테레오 영상에서 깊이가 나오는 이유
좌우 카메라  -  떨어진 두 시점에서 같은 장면을 봄. 두 카메라 중심 사이 거리가 베이스라인 B (로봇 성능 비교의 “기준선”과는 다른 뜻)
시차와 깊이  -  정렬한 좌우 영상에서 같은 점의 가로 위치 차이가 시차 d. 이상적으로 Z = fB/d, 같은 장치에서 가까운 물체일수록 시차가 큼
대응점  -  두 영상에서 같은 물리적 표면을 가리키는 점. 무늬가 없거나 반사되는 표면은 대응 찾기가 어려움 → FoundationStereo는 이 대응을 학습
공식 영상을 보기 전 예측: 멀리 있는 물체는 시차가 작아 1픽셀의 시차 오차가 깊이에 더 큰 영향을 줄 수 있음

평균, 중앙값, 노름 읽기
벡터와 노름  -  벡터는 순서 있는 숫자 묶음, 유클리드 노름은 성분 제곱합의 제곱근(길이). [3, 4]의 길이는 5
내적  -  대응 성분끼리 곱해 더한 값. [1, 2, 3]과 파랑 축 [0, 0, 1]의 내적은 3 → 두 벡터 길이로 나누면 코사인 유사도
중앙값의 효과  -  [0.49, 0.50, 2.00] m의 평균은 약 1.00 m, 중앙값은 0.50 m. 소수의 깊이 이상값에 덜 민감하지만 대부분이 잘못되면 역시 실패
카메라 보정은 센서 기하를 추정하는 작업, 18강의 실행 예산 보정은 허용 턴 수를 바꾸는 작업 → 무엇을 바꿨는지 단위와 함께 적기

“파란 블록”은 어느 좌표에 있나요?
장면에서 표면점으로: 색 이름으로 픽셀을 선택 → 깊이로 점을 복원하고 월드 좌표로 이동 → 보이는 면의 중앙값이 큐브 중심과 얼마나 다른지 비교
(슬라이드의 사진 두 장: 시작 RGB / 깊이가 있는 파랑 영역)
질문: 보이는 면의 중앙값과 블록 중심은 같을까? → 카메라는 가까운 표면을 봄 → 보이지 않는 뒷면까지 포함한 블록 중심과 대표점이 달라짐

계산 · 같은 픽셀에서 깊이만 바꾸기
조건: fx = fy = 600 px, 주점 (320, 240), 관측 픽셀 (380, 270)
```text
Z = 1 m → (0.10, 0.05, 1.00)
```

16강 · VLA 행동 후보와 어댑터
학습된 정책의 출력 7개를 검사해 관절 목표로 바꾸기

개념 · 시연으로 정책을 학습한다는 뜻
정책(policy)  -  관측과 지시에서 행동을 고르는 규칙 또는 모델 · Waffle에서는 시작 영상 + 지시 + 로봇 상태를 받아 목표 관절의 시간 순서를 냄
모방학습  -  시연자가 어떤 상황에서 어떤 행동을 했는지 배움 · 행동 복제 = 같은 관측에서 시연 행동에 가까운 출력을 내도록 모델 값을 조정
회귀와 가중치  -  회귀는 목표각 같은 연속 수치를 예측 · 가중치(weight)는 특징이 출력에 미치는 정도 · 학습 = 시연과 예측의 오차를 줄이도록 가중치 조정
학습과 추론을 구분: 궤적 헤드의 가중치를 맞추는 과정은 학습, 저장한 가중치로 새 배치의 궤적을 구하는 과정은 추론

개념 · 인코더, 은닉값, 헤드
인코더(encoder)  -  이미지와 문장을 계산 가능한 특징으로 변환 · 부모 모델은 SmolVLM2 계열 시각·언어 표현 + 정규화한 로봇 상태를 함께 사용
은닉 표현  -  모델 내부 층의 출력 · 부모 행동 헤드의 마지막 층 앞 값을 꺼내 벡터 길이로 나누면 방향은 유지하고 크기만 맞출 수 있음
헤드(head)  -  특징을 과제의 출력으로 바꾸는 부분 · ColorPolicy는 색상 기하 특징 + 부모 VLA 특징을 모아 각 시점·행동 축의 수치를 계산
예시: 특징 [2, 3], 한 시점·한 축의 가중치 [4, 5]이면 출력 = 2×4 + 3×5 = 23 → 92×7칸마다 이 합을 구함

개념 · 단위가 다른 행동을 한 배열에 담기
행동 공간  -  허용하는 명령의 종류와 범위 · 배열 순서는 차체 선속도(m/s), 회전속도(rad/s), 팔 절대각 4개(rad), 그리퍼 위치(m)
정규화  -  서로 다른 단위·범위를 공통 척도로 변환 · 최솟값 L, 최댓값 H를 [−1, 1]에 대응시키면 실제 중간값이 0
역정규화  -  모델 수치를 물리 단위로 되돌림 · actions.py는 L + (a+1)(H−L)/2 사용 · 평균·표준편차 방식에는 다른 역변환식 필요
계산: 그리퍼 범위 −0.010~0.019 m에서 정규화 출력 0 → (−0.010 + 0.019) / 2 = 0.0045 m

개념 · 행동 후보가 한 번에 관절로 가지 않는 이유
어댑터(adapter)  -  모델 출력을 제어기 입력 형식에 맞춤 · adapt()는 축 순서, 일곱 값의 유한성, 범위, 차체 정지 조건을 검사
포화와 속도 제한  -  clip은 값을 범위 안에 묶음 · 실행기는 전체 범위뿐 아니라 현재 위치와 목표의 차이도 제한 · 0.35 rad/s 제한이면 0.25초당 최대 0.0875 rad
기록과 피드백  -  action은 예측 후보, applied는 실행기가 적용한 목표 · 관절의 실제 위치나 블록 위치는 물리 피드백 → 목표를 보냈다는 사실만으로 도달 여부를 정할 수 없음
4 Hz = 1초에 네 번 → 실행 간격 1/4초 · 시뮬레이션 시간과 영상을 재생하는 실제 시간도 구분

개념 · LoRA가 학습할 값의 수를 줄이는 원리
미세조정  -  기존 모델을 새 과제 데이터에 맞추는 학습 · 동결(freeze)은 선택한 가중치를 학습 중 그대로 두는 것
저랭크  -  랭크(rank)는 행렬이 표현하는 독립적인 방향 수 · 큰 변화 행렬을 폭 r인 두 작은 행렬의 곱 BA로 나타내면 변화의 랭크는 최대 r
LoRA  -  Low-Rank Adaptation · 기존 W를 동결하고 작은 A, B만 학습 · 512×512 층에서 r=8이면 A와 B는 합쳐 8,192개 값
이 계산은 적응 기법 비교용 · 수업의 Waffle 색상 체크포인트는 LoRA 대신 부모 특징 위에 궤적 회귀 헤드를 맞춤

개념 · 슬롯과 관계 토큰으로 논문 그림 읽기
토큰(token)  -  모델이 한 단위로 처리하는 입력 조각 · 언어는 단어나 단어 일부, 영상은 영역에서 뽑은 특징
슬롯과 어텐션  -  슬롯(slot)은 영상 속 대상을 요약하는 표현 · 어텐션(attention)은 관련 있는 입력 특징에 더 큰 가중치를 줘 어떤 정보를 모을지 결정
관계와 디코더  -  관계 토큰은 집게와 블록 같은 대상 간 상호작용을 담음 · 디코더(decoder)는 이런 표현을 받아 행동 등 필요한 출력을 계산
SlotVLA 그림에서 그릇 자체를 나타내는 경로와 집게가 그릇에 접근하는 관계를 나타내는 경로를 각각 찾기

개념 · 시간에 따라 로봇을 제어하는 두 방식
열린 루프(open loop)  -  시작 때 정한 행동을 이후 관측으로 다시 계획하지 않고 진행 · 색상 운반 정책이 첫 영상에서 92개 목표를 정하는 층
닫힌 루프(closed loop)  -  현재 관측을 다음 명령에 반영 · 이 실행기는 매 시점 관절 위치 q를 다시 읽고 q에서 허용한 이동량만큼 다음 목표 적용
롤아웃(rollout)  -  초기 상태에서 정책을 실제로 전개해 얻은 관측·행동의 연속 기록 · 에피소드(episode) = 시작부터 종료까지 한 번의 시험
같은 시스템 안에서도 상위 궤적 예측(열린 루프)과 하위 관절 적용(닫힌 루프)은 서로 다른 주기로 피드백을 쓸 수 있음

구조 · VLA가 반환한 일곱 값

q₁~q₄  -  팔 관절의 절대 목표각  -  rad
g  -  그리퍼 위치  -  m

계산 · 역정규화와 부분 적응

```python
trajectory = np.einsum('i,itj->tj', design, W)
# 한 칸의 같은 계산
```

RAG · 검색과 생성이 맡는 일
RAG(Retrieval-Augmented Generation)는 외부 문서에서 질문에 맞는 근거를 찾아 모델 입력에 붙인 뒤 답을 생성하는 방식. 규칙 문서를 바꾸면 검색되는 내용도 바뀜
용어  -  뜻
질의(query)  -  찾으려는 질문
청크(chunk)  -  독립적으로 검색할 문서 조각 · ID, 버전, 원문을 보관해야 근거를 되짚을 수 있음
프롬프트  -  모델에 전달하는 지시와 입력
문맥(context)  -  검색 원문을 넣고 ID와 인용문을 요청 · 이 예제의 생성 모델은 Qwen2.5 7B
7B는 약 70억 규모의 모델 파라미터. 검색된 문서 수나 답을 생성한 횟수가 아님

검색 원리 · 질문에 가까운 근거 고르기
방식  -  특징
희소 검색  -  단어 일치 같은 제한된 특징 사용 · retrieve()에서는 질문과 문서 검색어 집합이 공유하는 서로 다른 단어 수가 점수
밀집 검색  -  문장 · 문서를 학습한 숫자 벡터로 나타내 가까운 것을 찾음 · 동의어를 연결할 수 있지만 비슷한 구버전 문서가 섞일 수도 있음
필터  -  버전 같은 조건으로 후보를 거름
top-k  -  점수가 높은 k개 · 실습 기본값 k=2 · 일치 단어가 없는 조각은 후보로 넣지 않음
예: 질문 단어 {블록, 운반, 조건}, 문서 검색어 {운반, 블록, 촬영} → 교집합 2개 → 점수 2

근거와 인용 · 근거가 있다는 사실을 어디까지 믿을까
근거(evidence)는 판단을 뒷받침하는 자료, 인용(quote)은 원문 일부를 옮긴 문구. answer()는 반환 ID와 해당 원문의 부분 문자열을 대조
상태  -  뜻
cited  -  ID와 인용 대조 통과
unsupported  -  인용 검증 실패
no_evidence  -  검색된 근거가 없음
올바른 문장을 인용해도 질문과 무관할 수 있음
Ollama는 로컬에서 언어 모델 요청을 처리 · 코드는 HTTP 요청에 질문과 검색 문서를 JSON으로 보내고 모델 응답의 ID와 문구를 꺼냄
문서에 “0.5초”가 있으면 규칙의 출처는 확인 가능. 현재 블록이 그 규칙을 충족했는지는 stable_s와 물리 관측으로 판단

평가 · 검색 성공률과 답변 정확도의 분모
지표  -  분모  -  이 예의 값
근거 포함률  -  전체 질문 (질문마다 필요한 근거 하나, 상위 k개 안에 들어온 질문 수)  -  8/10 = 80%
조건부 정확도  -  근거가 들어온 질문만  -  6/8 = 75%
종단 간 정확도  -  전체 질문 (나머지 두 질문도 틀린 경우)  -  6/10 = 60%
질문: 근거가 없는 질문까지 버리고 75%만 보고하면 어떤 문제가 숨겨질까? → 검색 단계의 누락이 가려짐
퀴즈: k를 늘리면 어떤 비용이 생길까? → 불필요한 조각과 모델 입력 길이가 늘어날 수 있음
