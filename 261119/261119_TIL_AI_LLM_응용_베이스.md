LLM · 정의와 생성 과정
LLM(Large Language Model): 대량의 텍스트에서 토큰 간 통계적 관계를 학습한 신경망

토큰 ID  →  임베딩·문맥 처리  →  다음 토큰 분포  →  선택·문맥 추가

선택한 토큰을 문맥에 추가한 뒤 같은 연산을 반복합니다.
설명용 후보 확률: 옮겨 0.6 / 열어 0.3 / 기타 0.1
높은 생성 확률과 사실성·실행 가능성은 별개입니다.

토큰과 임베딩 · ID에서 벡터로
용어  -  의미  -  동작
토큰  -  모델이 처리하는 텍스트 단위 (단어와 일대일 대응 아님)  -  Tokenizer: 텍스트 → 토큰 ID 배열
임베딩  -  토큰의 특성을 표현하는 학습된 수치 벡터  -  Embedding: 각 ID에 해당하는 임베딩 행렬 E의 행 조회
설명용 ID [12, 87] → 벡터 [[0.2, −0.1], [0.7, 0.4]]
실제 분할 방식·어휘 크기·벡터 차원은 모델마다 다릅니다.

자기회귀 생성 · 조건부 확률의 연쇄
문맥 x(<t)  →  P(x(t) | x(<t))  →  토큰 선택 x(t)  →  문맥에 추가

P(x1, …, xn) = ∏ P(x(t) | x(<t))
확률의 연쇄 법칙으로 문장 확률을 조건부 확률의 곱으로 분해합니다.
예: P(옮겨 | 상자를) = 0.6 — 후보 확률은 문맥과 모델에 의존하며, 사실일 확률과 구분합니다.

학습과 추론 · 가중치 갱신의 차이
구분  -  흐름  -  코드
학습 (Training)  -  입력 + 정답 → 손실 → 기울기 계산 → 가중치 갱신  -  loss.backward(); optimizer.step()
추론 (Inference)  -  새 입력 → 예측, 가중치 고정  -  model.eval(); torch.no_grad() 문맥에서 model(x)
역전파는 손실의 기울기를 계산하고, Optimizer는 기울기에 따라 가중치를 갱신합니다. 일반적인 추론은 역전파·갱신을 생략합니다.

Attention · 관계 점수와 가중합
![[pdf_p09.png]]
Q: Query(질의) / K: Key(비교 대상) / V: Value(결합할 정보) — 입력 벡터의 선형 변환으로 생성
Attention(Q,K,V) = softmax(QKᵀ / √d_k)V
가중치 [0.8, 0.2]인 경우 출력 = 0.8v1 + 0.2v2

환각과 문맥 한계 · 오류의 구분
정보 부족·잘못된 전제에서도 그럴듯한 답을 생성할 수 있고, 긴 문맥의 정보가 누락·잘못 연결될 수 있습니다.

로컬 LLM · 메모리와 실행 조건
로컬 추론: 내려받은 모델 가중치를 자신의 컴퓨터에서 실행
Ollama: 모델 다운로드·실행·HTTP API 제공 도구
메모리 구성 = 가중치 + KV cache + 실행 버퍼 등
가중치 메모리의 거친 하한 ≈ 파라미터 수 × 비트 수 / 8
예: 4B × 4bit ≈ 2GB (전체 실행 메모리와 구분)

Ollama 설치 · Linux 실행 절차
다운로드  →  스크립트 검토  →  설치·버전 기록  →  서비스 확인
```bash
curl -fsSL https://ollama.com/install.sh -o install-ollama.sh
sh install-ollama.sh   # 스크립트 내용 확인 후 실행
```
OS·Ollama 버전·GPU 드라이버 버전을 기록합니다.
서비스가 실행 중이면 ollama serve를 중복 실행하지 않습니다.
연결 오류 점검: 포트 11434 → 서비스 상태 → 로그

모델 실행 · 태그와 환경 기록
명령  -  역할
ollama pull  -  모델 다운로드
ollama run  -  대화 실행
ollama list / ps  -  설치 목록 / 실행 상태
```bash
ollama pull qwen3:4b
ollama run qwen3:4b
```
모델 태그·실행 장비·버전을 기록하고 같은 평가 입력으로 비교합니다.

POST /api/chat에 model·messages·format을 전달합니다. format에 JSON Schema를 지정하고 stream:false로 완성 응답을 받습니다.
```python
payload = {"model": "qwen3:4b", "messages": messages,
           "format": SCHEMA, "stream": False}
```
message.content를 JSON으로 해석한 뒤 기존 명령 검증 함수를 호출합니다. 구조화 출력과 현장 의미 검사는 분리합니다.
