
• **2×2 행렬 (1차원 공간용)**
선(Line) 위에서 좌우로만 왔다 갔다 하는 1차원 공간.  좌표 (x) 뒤에 1을 붙여서 (x, 1).  
• **3×3 행렬 (2차원 공간용)**
2D 게임, 모니터 화면, 청소 로봇이 움직이는 바닥 평면용. 좌표 (x, y) 뒤에 1을 붙인 (x, y, 1).  
• **4×4 행렬 (3차원 공간용)**
우리가 사는 3D 공간, 3D 그래픽스, 로봇 팔의 표준. 좌표 (x, y, z) 뒤에 1을 붙인 (x, y, z, 1).  
• **5×5 행렬 (4차원 공간용)**
3차원 공간에 '시간(t)'을 합친 4차원 시공간을 계산하거나, 특수 상대성 이론, 고차원 물리 시뮬레이션. 좌표 (x, y, z, t) 뒤에 1을 붙인 (x, y, z, t, 1).  
• **N+1 × N+1 행렬 (N차원 공간용)**
인공지능(AI)이나 빅데이터 분석에서는 수십~수천 차원 공간의 데이터를 다루기도 한다.  
데이터 차원이 100개면 **101×101 행렬**을 만들어서 똑같은 트릭으로 계산해버려.
결국 한계는 전혀 없고, "내가 다루고 싶은 차원에 1만 더한 행렬"을 만들어 쓰면 전부 동차 좌표 변환 행렬.


# 동차 좌표 변환 4×4(SE(3))와 포즈 표현 3종
### 1. 동차좌표 — 차원을 하나 늘리는 트릭
   3D 점 (x, y, z) 뒤에 1을 붙여 4개 숫자로 만듭니다: (x, y, z, 1). 이것이 동차좌표(homogeneous coordinates) 입니다.
   
   ##### **도형의 평행이동**![[Pasted image 20260820091839.png]]
   
   **왜 평행이동은 행렬의 곱이 안 되는가**
   평행이동은 선형변환이 아니기 때문입니다. 선형변환은 반드시 원점을 원점으로 보내야 하는데($T(\mathbf{0})=\mathbf{0}$), 평행이동은 원점을 옮깁니다. 
   그래서 병진은 2×2(3×3) 행렬 곱으로 표현할 수 없고, 차원을 하나 늘리는 트릭이 필요합니다.   ![[Pasted image 20260820092458.png]]
   
   **회전+병진을 곱 하나로 - 4 x 4 의 유도**
   하지만 차원을 하나 늘리면 회전(곱셈)과 병진(덧셈)을 한 번의 행렬 곱으로 처리할 수 있게 됩니다. 
   점 뒤에 1을 붙여 (x,y,z,1) 로 만들면, 블록 행렬의 곱이 정확히 Rp+t 를 만들어 냅니다.
   덧셈(병진)이 곱셈 안으로 흡수되는 것.
   컴퓨터 그래픽스와 로봇공학이 공통으로 쓰는 표준 기법입니다.   ![[Pasted image 20260820092837.png]]

### 2. 4×4 동차변환행렬 SE(3)
   **4×4 동차변환행렬 SE(3)**
   왼쪽 위 3×3 이 회전 R(자세), 오른쪽 위 열이 병진 t(위치), 마지막 행은 항상 [0 0 0 1] 입니다.
   이 행렬 하나가 '좌표계 B의 점을 좌표계 A 기준으로 읽는' 변환 전체를 담습니다.   ![[Pasted image 20260820093228.png]]![[Pasted image 20260820093344.png]]
   - 해석: 4×4 행렬의 왼쪽 위 3×3 블록은 회전 $R$(18강), 오른쪽 위 열은 병진 $\mathbf{t}$(위치), 맨 아래 행은 항상 $[0\ 0\ 0\ 1]$ 입니다. 이 한 행렬이 "좌표계 B의 점을 좌표계 A 기준으로 옮기는" 변환 $T_{AB}$ 전체를 담습니다.

   **점과 방향 - 두 가지 case**
   같은 변환을 점(w=1)과 방향(w=0)에 적용한 결과입니다. 점은 회전+병진, 방향은 회전만 됩니다.
   법선을 점처럼 [n, 1] 로 변환하는 것이 실무의 대표적 버그입니다.   ![[Pasted image 20260820093602.png]]

### 3. 합성과 역변환
   **좌표계 체이 = 행렬 곱**
   합성: 좌표계가 여러 단계로 연결되면 변환을 순서대로 곱합니다. 이것이 TF2 의 실체입니다.   ![[Pasted image 20260820093759.png]]![[Pasted image 20260820093808.png]]
   - 해석: 물체가 카메라 좌표계로 측정되면, 이를 로봇 base 기준으로 알려면 체인을 곱합니다: $\mathbf{p}_{base} = T_{base\_link}\, T_{link\_cam}\, \mathbf{p}_{cam}$. 각 화살표가 하나의 4×4 변환이고, 이들을 곱한 결과가 전체 변환입니다. 이것이 14강 TF2가 내부에서 하는 계산입니다.
   
   **2D로 본 체인**
   base → link → camera 프레임과 물체를 2D 로 그린 것입니다.
   각 화살표가 하나의 동차변환이고, 물체의 base 좌표는 두 변환의 곱으로 나옵니다.   ![[Pasted image 20260820094024.png]]
   
   **역변환 공식 유도**
   역변환: 반대 방향 변환은 역행렬입니다. 동차변환은 구조 덕분에 일반 역행렬 없이 바로 구할 수 있습니다.
   회전은 전치($R^{-1}=R^{\top}$), 병진은 $-R^{\top}\mathbf{t}$ 로 재계산합니다.
   T 가 점을 Rp+t 로 보내므로, 되돌리려면 먼저 t 를 빼고 역회전 Rᵀ 를 곱하면 됩니다.
   이를 4×4 블록으로 다시 적으면 전용 공식이 나옵니다 — 일반 역행렬보다 빠르고 안정적입니다.  ![[Pasted image 20260820094542.png]]
   
   **동차변환 - 숫자로 풀기**
   Rz(90°) 회전 + x 로 1 이동을 4×4 로 만들고, 점과 방향에 적용합니다.   ![[Pasted image 20260820094848.png]]


### 4. 연립 선형방정식 — 변환을 거꾸로 푸는 일반적 도구
   동차변환은 구조가 특별해서 역변환 공식이 있었습니다. 하지만 일반적인 문제 — 트러스 부재의 힘, 회로의 전류, 캘리브레이션 파라미터, 궤적 다항식의 계수 — 는 연립 선형방정식으로 풀어야 합니다.
   
   **연립일차방정식 - 가감법**   ![[Pasted image 20260820095259.png]]
   이 소거 절차를 임의 크기로 체계화한 것이 가우스 소거법입니다.
   
   **해는 세 경우뿐 - case 별 기하**
   두 직선이 한 점에서 만나거나(유일해), 겹치거나(무수히 많은 해), 평행하거나(해 없음) — '해가 정확히 두 개'인 경우는 없습니다.
   서로 다른 두 해($\mathbf{x}_1, \mathbf{x}_2$)가 있으면 그 사이 모든 점($(1-t)\mathbf{x}_1 + t\mathbf{x}_2$)도 해가 되기 때문입니다(선형성).   ![[Pasted image 20260820095606.png]]![[Pasted image 20260820095629.png]]
   ㅁ
   **가우스 소거 - 전방 소거 + 후방 대입**
   첨가행렬을 상삼각으로 만든 뒤(전방 소거) 아래에서부터 거꾸로 풀어 올라갑니다(후방 대입).
   행 연산은 해를 바꾸지 않으므로 소거해도 답이 그대로입니다. FEA 가 푸는 것도 결국 이것입니다.   ![[Pasted image 20260820100241.png]]
   손으로 2~3원 연립방정식을 푸는 방법을 체계화한 것이 가우스 소거법이고, 이 알고리즘이 그대로 컴퓨터 코드가 됩니다. 유한요소해석(FEA)이 자동차 차체를 해석할 때 실제로 푸는 것도 수십만 원짜리 $A\mathbf{x}=\mathbf{b}$ 입니다.
   
   **가우스 소거 - 단계별 풀이**
   3원 연립방정식을 첨가행렬로 적고 소거 단계를 하나씩 밟습니다.   ![[Pasted image 20260820100637.png]]
   
   **피벗팅 - 작은 수로 나누지 않기**
   피벗(대각 원소)이 0에 가까우면 나눗셈에서 반올림 오차가 폭발적으로 증폭됩니다.
   각 단계에서 절댓값이 가장 큰 원소를 피벗으로 올리는 것이 부분 피벗팅입니다.
   MATLAB의 백슬래시 연산자 A\b, NumPy의 np.linalg.solve(A, b) 는 내부적으로 부분 피벗팅을 포함한 가우스 소거(LU 분해) 를 수행합니다. 여러분이 직접 피벗팅을 구현할 일은 드물지만, 왜 그 함수를 써야 하는지는 알아야 합니다.   ![[Pasted image 20260820100844.png]]
   
   **피벗 크기에 따른 오차 - case 실험**
   피벗 ε 을 줄여가며 해의 오차를 실측한 그래프입니다. 피벗팅이 없으면 ε≈1e−13 부근에서 오차가 치솟습니다.
   np.linalg.solve 는 부분 피벗팅을 포함하므로 전 구간에서 안정적입니다.   ![[Pasted image 20260820101019.png]]
   
   **피벗팅 유무 - 숫자로 확인**
   ε = 1e−14 에서 같은 방정식을 두 방법으로 푼 실제 결과입니다.
   같은 방정식, 같은 컴퓨터 — 계산 '순서'만으로 답이 달라집니다.   ![[Pasted image 20260820101141.png]]
   

### 5. 역행렬과 Cramer 공식 — 그리고 그 한계
   **역함수와 역수**   ![[Pasted image 20260820101507.png]]
   행렬판이 A⁻¹A = I. '0으로 나눌 수 없다'에 해당하는 조건이 det A ≠ 0 입니다.
   
   **존재 조건, 2x2공식, Cramer**
   역행렬의 존재는 det ≠ 0 과 완전히 같은 말입니다(rank = n, 유일해와도 동치).
   정방행렬 $A$ 에 대해 $AA^{-1}=A^{-1}A=I$ 를 만족하는 $A^{-1}$ 이 존재하면 $A$ 를 가역(invertible) 이라 합니다.
   일반적인 크기에서는 수반행렬(adjugate) 공식도 있지만, 실제 계산은 첨가행렬 $[A | I]$ 에 가우스-조던 소거를 적용해 $[I | A^{-1}]$ 를 얻는 방법을 씁니다.
   Cramer 공식은 손계산·이론용 — 여인수 전개로 계산하면 O(n!) 이라 n=20 만 돼도 사용 불가입니다.   ![[Pasted image 20260820103108.png]]
   a
   **solve vs inv - 답은 같아도 비용이 다르다**
   x = A⁻¹b 로 푸는 것은 solve 보다 연산이 약 3배 많고 오차도 더 쌓입니다.
   역행렬 자체가 필요한 경우가 아니면 항상 solve 계열 함수를 씁니다.   ![[Pasted image 20260820103312.png]]

### 7. 포즈 표현 3종
   **무엇을 언제 쓰는가**
   포즈 = 위치 + 자세. 위치는 항상 (x,y,z) 지만 자세는 세 가지 그릇이 있습니다.
   좌표를 실제로 변환할 때는 행렬(동차변환), 저장·통신·보간에는 쿼터니언 — 이것이 실무 규칙입니다.

| 표현    | 숫자  | 장점                | 단점         | 주 용도              |
| ----- | --- | ----------------- | ---------- | ----------------- |
| 오일러 각 | 3   | 사람이 읽기 쉬움         | 짐벌락, 순서 모호 | 사람에게 보여줄 때, 설정 파일 |
| 회전행렬  | 9   | 좌표 변환에 바로 곱함      | 무겁고 오차 누적  | 좌표 변환 계산          |
| 쿼터니언  | 4   | 보간·합성에 강함, 짐벌락 없음 | 직관성 낮음     | 저장·통신·보간(ROS2 기본) |
ROS2 의 geometry_msgs/Pose 가 자세를 쿼터니언으로 담는 이유
