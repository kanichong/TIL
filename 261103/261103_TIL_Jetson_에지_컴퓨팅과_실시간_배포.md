완료 후  -  출력 텐서 사용  -  완료 동기화·후처리·결과 age 검사
GPU에 작업을 제출한 시점과 GPU가 계산을 마친 시점은 다릅니다.

동적 shape와 최적화 프로파일
범위  -  예시 NCHW  -  의미
min  -  1 × 3 × 320 × 320  -  허용할 가장 작은 입력
opt  -  1 × 3 × 640 × 640  -  최적화의 대표 입력
max  -  1 × 3 × 960 × 960  -  허용할 가장 큰 입력
고정 shape  -  모든 범위를 640으로  -  단순한 메모리·검증 경로
검증  -  경계와 실제 사용 해상도  -  정확도·지연·메모리 확인
예시는 설계 설명용이며 모델이 지원하는 해상도와 stride를 확인해야 합니다.

정밀도를 줄이면 무엇을 잃고 얻는가
표현  -  표현 방식  -  설계 판단
FP32  -  넓은 범위·높은 정밀도  -  비교 기준과 민감 연산
FP16  -  16비트 부동소수점  -  범위 초과·작은 값 소실 검사
INT8  -  정수 + scale/zero point  -  분포 대표성·클리핑 검사
혼합 정밀도  -  연산별 dtype/QDQ  -  민감 층은 높은 정밀도 유지
비트 수 감소가 곧 정확도 유지나 일정한 배속 향상을 보장하지 않습니다.

FP16·INT8을 검토하는 이유
정밀도  -  왜 검토하는가  -  우리 과제의 확인점
FP32  -  비교 기준과 민감 계산  -  기준 mAP·중심 오차 저장
FP16  -  메모리·대역폭·GPU 계산 비용 절감 가능  -  작은 퍽·멀리 있는 태그 주변 오차
INT8  -  더 작은 표현과 정수 연산 활용 가능  -  어둠·반사·가림을 포함한 대표 데이터
선택  -  빠른 정밀도 중 허용 정확도를 만족하는 것  -  속도만 좋아지고 집기 실패가 늘면 미채택
정밀도를 낮추는 목적은 제한된 자원에서 필요한 주기를 확보하는 것입니다. 정확도 손실에는 허용선을 둡니다.

TensorRT 최적화의 주요 기능
![[pdf_p32.png]]
융합, 정밀도 선택, 커널 튜닝이 어느 비용을 줄이는지 설명합니다.

INT8의 핵심은 눈금 간격이다
실수 x  →  q = clip(round(x/s) + z)  →  정수 q (−128 … 127)  →  복원 x̂ = s(q − z)

범위를 넓히면 이상치는 살지만 작은 차이를 구분하기 어렵습니다.

캘리브레이션 세트는 현장을 대표해야 한다
축  -  포함할 사례  -  분리 규칙
물체  -  빨강/초록 · 직육면체/원기둥  -  희귀 클래스 누락 금지
자세  -  서기·눕기·부분 가림  -  같은 장면 연속 프레임 누수 방지
빛  -  밝음·어두움·아크릴 반사  -  실제 카메라 분포도 추후 추가
거리  -  크게 보임·작게 보임  -  입력 해상도·전처리 동일
역할  -  대표 샘플 수백 장부터  -  calibration / validation / test 분리
수량만 늘리는 것보다 빠진 상황을 채우는 것이 먼저입니다.

Q/DQ로 양자화를 그래프에 표현하기
요소  -  의미  -  점검할 내용
QuantizeLinear (Q)  -  실수 텐서를 scale 기준으로 양자화  -  scale·zero point·dtype
DequantizeLinear (DQ)  -  양자화 값을 계산용 실수로 표현  -  Q와 대응하는 scale
가중치 / activation  -  각 텐서의 범위가 다름  -  채널별 / 텐서별 설정
TensorRT 빌드  -  지원되는 패턴을 낮은 정밀도 커널로 최적화  -  실제 레이어 dtype·fallback
최종 평가  -  양자화 오차를 과제 지표로 판단  -  mAP·중심 오차·정책 성공률
INT8 파일을 만들었다는 사실만으로 전체 그래프가 INT8 커널로 실행되지는 않습니다.

TRT 10.x와 11.x 명령을 섞지 않는다
기능  -  10.x 기존 경로  -  11.x 경로
FP16  -  --fp16 (weak typing)  -  모델 dtype/Cast → 빌드
INT8  -  기존 calibrator 또는 Q/DQ  -  Q/DQ 모델 → 빌드
민감 층  -  precision 설정 가능 경로  -  모델 그래프에 dtype 표현
측정 전달 비용  -  포함 옵션 확인  -  기본 제외; includeDataTransfers
첫 명령  -  trtexec --help  -  trtexec --help
설치된 버전을 읽고 그 버전에 맞는 명령을 선택합니다.

모델마다 판정 지표가 다르다
모델  -  필수 지표  -  추가 확인
YOLO  -  mAP50-95·클래스별 recall  -  작은 물체·가림·오검출
BC 정책  -  성공률·행동 오차  -  접촉 직전 미세 행동
Diffusion 정책  -  성공률·전체 K-step 지연  -  seed·denoise step 고정
퍽 CenterPose  -  중심 mm·축/대칭 오차  -  유효 출력 비율도 함께
AprilTag  -  ID recall·오ID·위치 오차  -  검출기가 DNN 양자화 대상인지 구분
양자화는 평가 조건을 고정한 실험으로 판단합니다.

Jetson은 작은 GPU PC와 다르게 설계한다
![[pdf_p40.png]]
- Arm64 CPU + Ampere GPU
- 8GB 공유 메모리
- 전력·온도·대역폭이 함께 제한
- 모델만 올리는 것이 아니라 센서와 프로세스 전체를 배치한다.

Nano Super에는 DLA가 없습니다. Orin NX·AGX의 자원 배치를 그대로 옮기지 않습니다.

Jetson에서 에지 컴퓨팅을 하는 이유
요구  -  온보드 추론의 역할
카메라와 로봇이 현장에서 이동  -  로봇 가까이에서 영상 처리와 판단 수행
네트워크 지연·끊김이 발생  -  매 프레임을 외부 서버에 보내는 의존성 축소
여러 센서와 구동기가 연결됨  -  추론 결과를 ROS 노드와 제어기에 전달
PC와 역할 분리  -  PC는 학습·시뮬레이션, Jetson은 추론·진단
여전히 필요한 것  -  전원·냉각·메모리 예산, 독립적인 제어 타임아웃
에지 컴퓨팅은 데이터가 생기는 곳 가까이에서 계산하는 방식입니다. Jetson은 그 계산을 수행하는 온보드 장치입니다.
